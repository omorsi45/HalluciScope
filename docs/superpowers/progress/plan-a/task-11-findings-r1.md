# Task 11 open findings (round 1), from the review, with controller rulings

1. (Critical) Throttle check-then-act race (backend/auth/service.py:135-136 read, 168/171 scrypt, 174-175 increment). Counters are read without a lock under READ COMMITTED and only incremented after the slow password check. Measured: 30 concurrent wrong-password logins on one account (pool max_size=10) gave 13 invalid_credentials and an email counter of 13, against a limit of 5. Fix: reserve the attempt atomically before checking credentials with a conditional upsert: `insert ... values (%s, %s, 1) on conflict (key, window_start) do update set failures = auth_throttle.failures + 1 where auth_throttle.failures < %s returning failures`. No returned row means throttled. Refund the email reservation if the IP key is throttled. On success, delete the email key as now and decrement the IP key so it counts failures only. Add a test firing about 20 logins with asyncio.gather (pool max_size >= 10) asserting at most 5 invalid_credentials and the rest too_many_attempts.
2. (Important) Login holds a pooled connection in an open transaction while scrypt runs (transaction opened at service.py:131 encloses asyncio.to_thread at 168/171), so unauthenticated callers can exhaust the pool. Fix: split login into (a) a short transaction that looks up the user and reserves the throttle slot, (b) password verification with no transaction or connection held, (c) a short transaction that writes the session and login audit, or the login_failed audit.
